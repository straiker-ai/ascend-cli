usage: ascend [--json] [--token TOKEN] [--base URL] <command> [<verb>] [flags] adapter
       [-h] [--json] [--token TOKEN] [--base BASE] [--bridge-base BRIDGE_BASE]
       {list,show,configs,layers,validate,bundle,build} ...

Build and inspect adapter configs directly.

An adapter is HOW the CLI speaks one target's protocol, so it is
a property of a target rather than a separate thing to manage.
`ascend target add` derives it from a URL, a cURL file or a .har,
proves it against the live endpoint and stores it. These verbs
remain for the cases that need the lower level.

positional arguments:
  {list,show,configs,layers,validate,bundle,build}
    list                list registered adapter types
    show                print a saved adapter config (secrets masked)
    configs             list adapter configs on disk (incl. shipped examples)
    layers              ==SUPPRESS==
    validate            HARD GATE: run one prompt through a config against the live target
    bundle              write the hand-over bundle for a config: adapter.json (env: refs only),
                        manifest, secrets template, relay/ container, shim/ service + Lambda,
                        vendored runtime
    build               build a validated adapter from a URL / HAR / curl / API / spec

options:
  -h, --help            show this help message and exit
  --json                machine-readable JSON output (default: False)
  --token TOKEN         Straiker PAT (s6r_pat_...) or JWT; else $STRAIKER_PAT (default: None)
  --base BASE           v3 API base URL (default: https://api.prod.straiker.ai/api/v3)
  --bridge-base BRIDGE_BASE
                        Ascend lease-service base URL (where bridges fetch probes and post
                        results) (default: https://ascendai-bridge.prod.straiker.ai)
--- stderr
